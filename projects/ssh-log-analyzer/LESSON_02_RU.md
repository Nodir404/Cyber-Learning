# Занятие 2: частые неудачные попытки входа

Теперь программа умеет проверять правило: «не меньше 5 неудачных попыток
с одного IP за любые 5 минут». Совпадение отмечается строкой `ALERT`.
Это повод изучить события подробнее; сам по себе счётчик не доказывает атаку.

## Получи новую версию

Пока изменения находятся в отдельной ветке, в терминале выполни строки по очереди:

```bash
cd ~/Cyber-Learning
git fetch origin
git switch --track origin/feature/ssh-burst-detection
cd projects/ssh-log-analyzer
```

Если такая локальная ветка уже есть, используй `git switch feature/ssh-burst-detection`.
Если Git сообщает о несохранённых изменениях, сохрани их перед переключением.

## Запусти проверку

```bash
python3 analyzer.py data/sample_burst.log --detect-bursts --year 2026 --threshold 5 --window-seconds 300
```

- `--detect-bursts` включает проверку по времени.
- `--year 2026` задаёт год: в строках учебного лога его нет.
- `--threshold 5` означает «не меньше 5 неудачных попыток».
- `--window-seconds 300` задаёт окно в 300 секунд, то есть 5 минут.

В конце вывода будет:

```text
ALERT 192.0.2.10: 5 failed attempts between 2026-10-28 10:00:00 and 2026-10-28 10:04:00
```

Общая сводка содержит 1 успешный вход, 7 неудачных попыток и 3 разных IP.
У адреса `192.0.2.10` всего 6 неудачных попыток. Но в одном окне на 5 минут
помещаются только 5 из них — поэтому в предупреждении указано число 5.

## Проследи окно времени

Открой `data/sample_burst.log`. Неудачные попытки с `192.0.2.10` имеют время:

| Время | Попадает в окно 10:00–10:05? |
|---|---|
| 10:00:00 | Да |
| 10:00:20 | Да |
| 10:01:00 | Да |
| 10:03:00 | Да |
| 10:04:00 | Да |
| 10:10:00 | Нет |

Программа проверяет окна, начинающиеся у событий, а не только фиксированные
отрезки вроде 10:00–10:05 и 10:05–10:10. Поэтому серия между 10:04 и 10:08
тоже может попасть в одно окно.

## Измени один параметр

Подними порог с 5 до 6 и повтори запуск:

```bash
python3 analyzer.py data/sample_burst.log --detect-bursts --year 2026 --threshold 6 --window-seconds 300
```

Предупреждение исчезнет: шести попыток в любом пятиминутном окне здесь нет.
Сводка останется прежней — параметры проверки не меняют число записей в логе.

Теперь верни порог 5 и поставь окно 600 секунд. В одно окно попадут все
6 попыток с этого адреса, включая событие ровно на границе 10:10:00.

## Посмотри реализацию

В `analyzer.py` найди `detect_bursts()`:

1. Функция собирает время неудачных попыток отдельно для каждого IP.
2. Сортирует время от раннего к позднему.
3. Перемещает правую границу окна к следующему событию.
4. Убирает слева события, которые стали старше окна.
5. Запоминает самое большое число попыток внутри окна.

На каждый IP выводится одно предупреждение с максимальным числом попыток.
Записи с некорректным временем подсчитываются отдельно и не участвуют в окне.
Все даты должны относиться к одному указанному году и одной системе времени.
